你的工厂，实时跑在你自己的服务器上。

演示是一家有三个工厂的锻造公司，设备数据由模拟设备经 MQTT、Modbus、OPC UA 发来。

在后台把工厂搭出来

选一个内置模板，或者用几句话描述你的工厂让 AI 来写，或者直接粘贴配置。工厂、产线、设备和工艺路线边改边排进平面图。

  • 内置六个行业锻造、机加工、汽车、食品饮料、电池、空调。
  • 缺的 AI 来补没有陶瓷、制药的行业包？AI 写一个：产品、设备、工艺路线，引擎检查通过才让你建。
  • 模板带得走把你的工厂存成模板，导出成文件，在另一台服务器上导入。

按 ERP 的工单生产

ERP 下达生产工单，每张排到做这个料号的产线上，产线按交期先后生产。开工、完工都回传给 ERP。

  • 推或者拉ERP 用自己的令牌把工单推过来，或者由服务器去 ERP 取，字段对应可配，按行返回数组的也能读。
  • 回调带签名开工、完工的工单连同合格数、报废数一起回传，带 HMAC-SHA256 签名。
  • 和真实工厂一样没有工单的产线停下等单。演示时也可以让它照常仿真。

问它现在怎么样了

助手根据孪生、工单和你的资料回答：哪台设备停了，哪张工单会延期，作业指导书怎么写的。在后台里，助手提出的改动要你确认才执行。

它懂你的工艺

每个工厂、产线、工位、设备、产品、供应商和客户都是知识图谱里的一个节点，工厂一改就重建。上传的资料和其中提到的设备、产品连在一起，所以问 IH-101 能找到中频感应加热炉的工艺卡。

接上你已有的系统

用 MQTT 上报的设备按约定的主题发数据，不用配置。已有的 PLC、网关和 broker，服务器直接去读。

设备MQTT，一个读数一个主题sf/{公司}/{工厂}/{设备}/{字段}
PLC 和网关Modbus TCP、OPC UA、你自己的 MQTT broker
ERP生产工单，推送或拉取
SmartFactory你服务器上的一个程序
浏览器孪生和后台，电脑和手机都能用

装在一台 Linux 服务器上

  1. 下载对应架构的安装包
    tar xzf smartfactory-v0.1.2-linux-amd64.tar.gz
cd smartfactory-v0.1.2-linux-amd64
  2. 装成系统服务
    sudo ./smartfactory install

    systemd 服务，独立的系统用户，立即启动，开机自启。以后用新版本再执行一次就是升级。

  3. 登录，搭你的工厂
    sudo cat /var/lib/smartfactory/initial-admin-token

    用这个令牌打开 http://你的服务器:4720/admin。

macOS、Windows 上直接运行 smartfactory -config smartfactory.json。要用 AI 助手，在 /etc/smartfactory/env 里配一个兼容 OpenAI 接口的大模型。

工厂的数据留在你自己的服务器上

一个目录场景、仿真状态、账号、知识库和工单都在 /var/lib/smartfactory，备份它就是备份整个工厂。
不往外报数据服务器只连你接上的东西：你的设备、你的 ERP、你的大模型。
